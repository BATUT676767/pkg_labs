# Отчёт по лабораторной работе №1

**Тема:** цветовые модели.  
**Вариант 2:** RGB ↔ CMYK ↔ HLS.

## 1. Назначение приложения

Разработано браузерное приложение для выбора цвета и изучения его представления в трёх цветовых моделях. Каждая модель поддерживает числовые поля, ползунки и выбор из палитры. Изменение компоненты вызывает автоматическое обновление остальных представлений и образца цвета.

Программа написана на HTML, CSS и JavaScript. Математические преобразования выполняются без внешних библиотек. Для дополнительных расчётов реализованы XYZ и LAB с выбором освещения.

## 2. Интерфейс и допустимые значения

Основная область содержит панели RGB, CMYK и HLS. Рядом расположены открытая палитра, образец цвета, HEX-поле и настройки освещения и коррекции диапазона. Под моделями находятся выбор UCR/GCR и сила замены серого. На узких экранах блоки располагаются вертикально.

| Модель | Компоненты | Диапазон |
| --- | --- | --- |
| RGB | R, G, B | 0–255 |
| CMYK | C, M, Y, K | 0–100% |
| HLS | H | 0–360° |
| HLS | L, S | 0–100% |

HLS соответствует HSL, но координаты расположены в порядке «тон, светлота, насыщенность». В RGB используется аддитивное смешение, в CMYK — математическая модель субтрактивного цветоделения.

Значения пересчитываются при событии `input`. Активное поле не перезаписывается во время отображения; при `change` или потере фокуса его значение приводится к представлению с тремя знаками после запятой. Промежуточные расчёты не округляются. Шаг основных ползунков составляет 0,1, числовые поля допускают дробный ввод.

Пустые и некорректные значения не заменяют последний корректный цвет. Для CMYK и HLS значения ограничиваются диапазоном компоненты. При вводе RGB за пределами 0–255 применяется выбранная стратегия обработки охвата.

## 3. Организация кода и пересчёт

Код разделён на три слоя:

- `ColorModel` в `model.js` содержит чистые математические функции без обращения к DOM.
- `ColorView` в `view.js` создаёт панели и отображает координаты, цвет, палитры и градиенты.
- `Controller` в `controller.js` хранит состояние и связывает события интерфейса с расчётами.

RGB используется как общее представление для обмена между основными моделями:

```
CMYK ↔ RGB ↔ HLS
         ↕
        XYZ ↔ LAB
```

После действия пользователя контроллер получает новые значения, вычисляет RGB и остальные представления, обновляет элементы интерфейса и градиенты. При непосредственном редактировании CMYK или HLS введённые координаты исходной модели сохраняются. Это важно, поскольку одному RGB могут соответствовать разные варианты цветоделения, а для серого цвета тон неоднозначен.

Выбор другого цвета или изменение алгоритма цветоделения вызывает повторный расчёт CMYK из RGB. Присваивание значений DOM-элементам не создаёт событий `input`, поэтому бесконечный цикл обновлений не возникает.

## 4. Преобразования RGB и HLS

Для RGB → HLS сначала нормализуются компоненты:

```
r = R / 255, g = G / 255, b = B / 255
hi = max(r, g, b)
lo = min(r, g, b)
d = hi − lo
L = (hi + lo) / 2
```

Если `d ≤ 10⁻¹²`, принимается `H = S = 0`. Иначе:

```
S = d / (1 − |2L − 1|)
H / 60 = (g − b) / d       при hi = r
H / 60 = (b − r) / d + 2   при hi = g
H / 60 = (r − g) / d + 4   при hi = b
```

Тон нормализуется по модулю 360. Светлота и насыщенность выводятся в процентах.

Для HLS → RGB используются нормализованные `l = L/100`, `s = S/100`:

```
C = (1 − |2l − 1|)s
X = C(1 − |(H/60 mod 2) − 1|)
m = l − C/2
```

Сектор тона определяет перестановку `(C, X, 0)`. К каждой компоненте добавляется `m`, затем результат умножается на 255. Значение 360° эквивалентно 0°.

## 5. CMYK и алгоритмы цветоделения

Исходные субтрактивные компоненты:

```
q = (1 − R/255, 1 − G/255, 1 − B/255)
gray = min(q)
chroma = max(q) − gray
α = сила замены серого / 100
```

### GCR

Серая составляющая заменяется чёрной во всём диапазоне:

```
K = α · gray
```

### UCR

Замена сосредоточена в глубоких тенях и ослабляется для насыщенных цветов:

```
t = clamp((gray − 0.5) / 0.5, 0, 1)
K = α · gray · t²(3 − 2t) · (1 − chroma)
```

После определения чёрной компоненты рассчитываются остальные:

```
(C, M, Y) = (q − K) / (1 − K)
```

Если `K ≥ 1 − 10⁻¹²`, возвращается `(0, 0, 0, 100)` для исключения деления на ноль. Компоненты переводятся в проценты.

Обратное преобразование при C, M, Y, K в процентах:

```
R = 255(1 − C/100)(1 − K/100)
G = 255(1 − M/100)(1 − K/100)
B = 255(1 − Y/100)(1 − K/100)
```

Используемая модель не учитывает профиль принтера, свойства бумаги и красок; точное воспроизведение печати требует ICC-профиля.

## 6. Освещение и дополнительные XYZ/LAB

Выбор D65, D50 или E пересчитывает матрицу и внутренние координаты XYZ/LAB, сохраняя экранный sRGB. Значения доступны через `Controller.getColorimetry()`, который возвращает копии матрицы и координат. Отдельные поля ввода для XYZ и LAB не предусмотрены.

| Точка | x | y |
| --- | ---: | ---: |
| R | 0.64 | 0.33 |
| G | 0.30 | 0.60 |
| B | 0.15 | 0.06 |
| D65 | 0.3127 | 0.3290 |
| D50 | 0.34567 | 0.35850 |
| E | 1/3 | 1/3 |

Для каждой точки формируется вектор `(x/y, 1, (1−x−y)/y)`. Из первичных цветов составляется матрица P. Базовая матрица для D65 вычисляется как:

```
S = P⁻¹ · W_D65
M_D65 = P · diag(S)
```

Переход к выбранной белой точке производится хроматической адаптацией Bradford:

```
A = B⁻¹ · diag((B · W_target) / (B · W_D65)) · B
M_target = A · M_D65
```

Деление в отношении векторов покомпонентное. Матрица B задаёт базис Bradford; готовые матрицы RGB → XYZ для каждого освещения не записаны. Обращение матриц реализовано методом Гаусса–Жордана с выбором ведущего элемента.

Перед переходом к XYZ компоненту `c = RGB/255` линеаризуют:

```
linear(c) = c/12.92                       при c ≤ 0.04045
linear(c) = ((c+0.055)/1.055)^2.4          иначе
```

Линейный вектор умножается на матрицу; XYZ масштабируется на 100. Обратный переход использует обратную матрицу и функцию:

```
gamma(t) = 12.92t                        при t ≤ 0.0031308
gamma(t) = 1.055t^(1/2.4) − 0.055         иначе
```

Для LAB используются отношения XYZ к выбранной белой точке и функция:

```
δ = 6/29
f(t) = ∛t                    при t > δ³
f(t) = t/(3δ²) + 4/29         иначе
L* = 116f(Y/Yn) − 16
a* = 500(f(X/Xn) − f(Y/Yn))
b* = 200(f(Y/Yn) − f(Z/Zn))
```

Обратное преобразование восстанавливает `fy=(L*+16)/116`, `fx=fy+a*/500`, `fz=fy−b*/200`. Затем применяется `f⁻¹(t)=t³` при `t>δ`, иначе `3δ²(t−4/29)`, и результат умножается на белую точку.

## 7. Коррекция диапазона RGB

Функция `gamut` возвращает скорректированный RGB и признак изменения. Значимый выход за диапазон определяется с допуском `10⁻⁷`.

**Clipping** независимо ограничивает каждый канал:

```
c' = min(255, max(0, c))
```

**Scaling** сначала сдвигает отрицательный минимум, затем применяет общий масштаб:

```
lower = min(0, R, G, B)
v = (R, G, B) − lower
upper = max(255, v_R, v_G, v_B)
v' = v · 255 / upper
```

В конце каждого канала касается ограничение 0–255 для защиты от численных погрешностей. Например, `(-10, 120, 300)` при Scaling становится примерно `(0, 106.935, 255)`.

Последний исходный RGB хранится в `rawRgb`: смена стратегии повторно обрабатывает его. После редактирования HLS/CMYK этот сохранённый RGB сбрасывается. О применённой коррекции выводится предупреждение.

## 8. Палитры и динамические градиенты

В каждой панели предусмотрены системный выбор цвета и десять готовых образцов. Отдельная двумерная палитра строится на Canvas: горизонтальная координата задаёт насыщенность, вертикальная — светлоту; тон выбирается отдельной полосой.

Палитра поддерживает нажатие и перетаскивание, а также клавиши-стрелки. Обычный шаг клавиатуры составляет один процентный пункт, с Shift — десять. Захват указателя позволяет продолжать выбор при перетаскивании за границы поля; координаты ограничиваются допустимыми значениями. Изображение палитры перестраивается при изменении тона, положение маркера обновляется при каждом изменении цвета.

Градиент каждого основного ползунка строится по **17 точкам**. В каждой точке изменяется только соответствующая компонента, остальные остаются равными текущим. Полученный цвет переводится в RGB и включается в CSS `linear-gradient`. Пересчёт выполняется синхронно при обновлении интерфейса.

## 9. Проверка реализации

Файл `tests.js` содержит функцию `runColorTests()`. Она возвращает количество выполненных и успешных проверок, а также список ошибок. Тесты независимы от DOM и не подключены к основной странице.

Проверяются:

- красный, зелёный, синий, белый, чёрный и серый цвета;
- HLS для основных цветов и эквивалентность 0°/360°;
- CMYK для красного, чёрного и белого;
- различия GCR и UCR в средних тонах и тенях;
- Clipping и Scaling на значениях за диапазоном;
- эталон LAB красного при D65;
- белая точка XYZ и белый/чёрный LAB для D65, D50 и E;
- 150 воспроизводимых наборов RGB с обратным HLS-переходом;
- обратный CMYK-переход для UCR/GCR при силе замены 0, 0.5 и 1;
- полный обратный переход RGB → XYZ → LAB → XYZ → RGB для трёх освещений.

Всего выполняется **1523 проверки**. Допуск основных сравнений — `10⁻⁷`, полного перехода через XYZ/LAB — `10⁻⁶`, округлённого эталона красного LAB — `0.001`. Результат запуска хранится в `test-results.json`.

Команда запуска тестов приведена в README.

## 10. Запуск программы и вывод

Для работы достаточно открыть `index.html` и хранить подключаемые JS-файлы рядом с ним. Автономная HTML-версия содержит те же слои внутри одного файла. Для публикации через GitHub Pages предусмотрен файл `.github/workflows/pages.yml`.

В результате реализовано интерактивное сравнение RGB, CMYK и HLS, ручное цветоделение UCR/GCR, выбор палитры, динамические градиенты и обработка некорректных значений. Дополнительные преобразования XYZ/LAB учитывают выбранную белую точку с хроматической адаптацией.
